THE COOKBOOK every trap below was hit and fixed for real, on chain, by corvid-agent

Arcron is a permissionless keeper network on Algorand. Anyone registers a recurring upkeep — a target application call, an interval in rounds, a fee escrow — and any keeper executes it when due. This kit is the integration path with the teeth marks left in: the ten traps below each cost a real transaction before they became comments in recipes/register.py.

Four contracts on this network are the reference implementations, registered and executing live: plod, waddle, arcron-beacon and epitaph — fleet cards below, upkeep rows on the live board.

THE TEN TRAPS numbered as they bit · each one is a comment in register.py at the line it guards
byte[][] NEEDS ITS OFFSET HEADER

A bare 4-byte selector hand-rolled as call_args fails register with a bare assert. A dynamic array of dynamic bytes carries u16 count + u16 offsets + u16 lengths.

FIX ArrayDynamicType(ArrayDynamicType(ByteType())).encode([selector]) → 0001 0002 0004 <selector> — 10 bytes, not 4.

THE MBR FORMULA

The box minimum balance is exact, and the contract asserts it: underpay and the group dies. Overpaying a guess strands the difference until cancel.

FIX 2,500 + 400 × (139 + len(encoded call_args)) µALGO → 62,100 for the 10-byte bare-selector encoding. Refunded in full on cancel.

THE BOX THAT DOESN'T EXIST YET

The group must reference the box register is about to create, and register assigns the id. A stale id — anyone else registered since your read — fails the group.

FIX box ref b"u" + itob(next_upkeep_id), read from keeper global state fresh every attempt. It's a race, not a bug: re-read, resubmit.

PUYA LOWERS Application TO uint64

The source says set_keeper(app: Application), but the ARC-4 signature is set_keeper(uint64)void. A selector hashed from the source matches nothing and dies with "err opcode".

FIX selector 0xc4c1d8f7 for set_keeper(uint64)void. The .arc56.json artifact is the authority, never the Python source.

app_params_get NEEDS THE APP AVAILABLE

Hand-TEAL set_keeper reading AppCreator fails "unavailable App" unless the keeper app rides in foreign_apps of that call.

FIX put the keeper in foreign_apps for the setup call. Inside keeper-driven hooks, Application(keeper).address works without naming it — keeper bots simulate first and auto-attach what simulation names (_resolve_execute_references).

POLICY 0 IS THE TRAP

CATCH_UP = 0 is what an undecided caller passes. It replays every missed interval: one due upkeep can demand many back-to-back executions and burn its whole escrow catching up — upkeep 18 spent everything and advanced 41 rounds against a 23,478-round backlog.

FIX pass SKIP_AHEAD = 1 deliberately. Next fire is always in the future, keeping the schedule's phase.

ZERO uint64 CREATE-ARGS

A create-arg left zero that was meant to hold the keeper id maps your cadence onto app 0 — an interval derived from nothing freezes the schedule for ~68 years of rounds.

FIX pass every uint64 create-arg explicitly; verify the stored keeper id on chain right after deploy, before registering anything.

FAIL-SOFT HOOKS

An assert after keeper auth rejects the execution, the keeper bot records a failure and backs the upkeep off exponentially — 1, 2, 4, 8 of its own intervals, capped near 1,286 rounds — persisted across restarts. Keep failing and your schedule quietly stops while escrow burns.

FIX hooks return on no-work and on too-early; they never assert after the keeper check. Record the problem in state and return.

THE FEE FLOOR

MIN_UPKEEP_FEE = 4,000 µALGO is asserted in register before anything is charged — a lower fee doesn't register at a reduced rate, it doesn't register at all. And a 1,000 µALGO app call underfunds the group.

FIX fee ≥ 4,000 µALGO per execution; the register group's app-call txn carries a 3,000 µALGO flat fee (the keeper's inner calls spend it).

THE SIGNATURE, VERBATIM

Transcribed from the Puya source, target_app: Application reads application and hashes to 0x7291d904 — a selector that matches no method and fails without saying why.

FIX register(pay,pay,uint64,byte[][],uint64,uint64,uint64,uint64,uint64,uint64)uint64 → sha512_256[:4] = 0x3636cfc6. Verify with recipes/selectors.py before every integration.

THE REGISTER RECIPE recipes/register.py — annotated at the lines the traps guard · mnemonic from BANK_MNEMONIC, never hardcoded 
# group order is load-bearing: [mbr_payment, funding_payment, app_call]
# TRAP 10 — verbatim; Puya lowered target_app: Application to uint64
REGISTER_SIG = "register(pay,pay,uint64,byte[][],uint64,uint64,uint64,uint64,uint64,uint64)uint64"
REGISTER_SELECTOR = sha512_256(REGISTER_SIG)[:4]  # == 0x3636cfc6

# TRAP 1 — byte[][] carries its own offset header: 0001 0002 0004 <selector>
call_args = ArrayDynamicType(ArrayDynamicType(ByteType())).encode([selector])  # 10 bytes

# TRAP 3 — the box register is ABOUT to create; read fresh every attempt
upkeep_id = read_global_uint(KEEPER, b"next_upkeep_id")
box_ref = (KEEPER, b"u" + upkeep_id.to_bytes(8, "big"))

# TRAP 2 — both payments to the keeper APP address, from the SAME sender:
# algosdk.logic.get_application_address(769891898)
#   = M4YFP33L5VIFRF53X53WUMQWBOWSLYQNBSSAJV2SORGF43L36XBY7OREUA
mbr = 2_500 + 400 * (139 + len(call_args))  # 62,100 µALGO for a bare selector
mbr_payment     = PaymentTxn(sender, sp, KEEPER_ADDRESS, mbr)
funding_payment = PaymentTxn(sender, sp, KEEPER_ADDRESS, funding)  # ≥ one execution

# TRAP 9 — fee ≥ 4,000 µALGO; the app call itself carries 3,000 flat
sp_app = suggested_params(); sp_app.flat_fee = True; sp_app.fee = 3_000
app_call = ApplicationNoOpTxn(sender, sp_app, KEEPER,
    app_args=[REGISTER_SELECTOR, itob(target_app), call_args,
              itob(interval), itob(fee), itob(SKIP_AHEAD),  # TRAP 6: never 0 by default
              itob(fee_cap), itob(fee_asset), itob(asset_fee)],
    boxes=[box_ref])
